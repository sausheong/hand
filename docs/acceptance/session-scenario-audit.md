# Durable-session scenario audit

This audit maps all nine M3.1 scenarios to fresh, uncached race-test records and states what each actually proves. Every referenced test passed and both source fingerprints stayed unchanged during the suites. These development checks do not qualify a clean final Hand candidate or a released Harness dependency.

| Scenario | Verified behaviour | Remaining evidence |
| --- | --- | --- |
| `legacy_backup_idempotent_import` | Legacy bytes preserved in a backup; import retains old and new sessions; repeat reconciliation creates neither duplicate sessions nor backups. | Run the same import through the released Hand binary on both supported native platforms. |
| `interrupted_migration` | Killed child at backup and replacement durability boundaries; original backup preserved; replacement complete; restart repair idempotent and writable. | Qualify the Hand startup import boundary as well as these Harness migration boundaries on the final candidate. |
| `branch_restart_compaction` | Compaction view survives reload and original branch history remains selectable; annotation persistence preserves branch selection. | One final built-Hand journey must combine branch creation, compaction, process restart and continuation of the selected branch. |
| `selected_leaf_persisted` | Selected older branch survives reload/rewrite and future append uses that parent; other branch retained; repaired Hand session preserves selected leaf on reopen. | Exercise branch selection and restart through the final Hand RPC or TUI interface. |
| `new_preserves_history` | Creating a new session retains legacy history and independent session records; reopening old and latest sessions preserves their separate histories. | Requalify the existing controller/binary journeys against the released dependency and clean candidate. |
| `two_process_writer_lock` | Second process denied a live Harness writer lease; death releases lease; recovered writer persists; catalogue lock also recovers after process death. | Run simultaneous final Hand processes against the same selected session, verifying visible refusal and subsequent recovery. |
| `truncated_tail_vs_interior_corruption` | Truncated final record recovered with backup; interior corruption refused with original bytes unchanged. | Verify final client diagnostics and backup paths on both platforms, in addition to these storage checks. |
| `disk_full_visible` | Disposable child imposes a real file-size limit; fork/export receive EFBIG, preserve source and selection, leave no partial publication and retry after restoring limit. Branch persistence failure is returned. | EFBIG is not ENOSPC. Add a controlled disk-full or equivalent explicitly justified fault path and verify user-visible failure during active persistence, not just manager errors. |
| `usage_attachments_export_restart` | 12 MiB attachment survives fork and standalone export reload after original blob store is moved; only referenced blobs copied. Usage origin and token totals survive reopen; inherited fork consumption excluded. | Combined storage journey now passed; see [supplemental evidence](combined-session-export.json). Final built-Hand totals/image presentation and platform qualification remain pending. |

[Machine-readable audit](session-scenario-audit.json) contains exact test identities, source fingerprints and hashed raw logs. Counts: 77 Hand sessionio and 172 Harness session test/subtest records; no failures or skips. Nine scenarios have development evidence; zero are marked finally qualified. This is a scope distinction, not a claim that no functionality is implemented.

The [built-client export supplement](binary-combined-export.json) now verifies separate Hand processes exporting and re-exporting the combined journal and attachment sidecars from independent homes, with the original store moved away. Catalogue reconstruction is explicit API setup; totals/image content are read back through storage APIs. This does not claim an import CLI or UI rendering qualification.

[Real ENOSPC supplement](session-enospc.json): a built Linux Hand process now reports exit 5 and the no-space diagnostic on a deliberately full 2 MiB tmpfs, preserves source and selection, removes temporary output and retries byte-identically after space is freed. This closes the EFBIG-versus-ENOSPC evidence gap for CLI export. Active conversation/UI writes and final platform qualification remain pending.

[Active conversation ENOSPC supplement](conversation-enospc.json): the built CLI now also reports persistence failure after a local provider request reaches a genuinely full tmpfs. Saved questions survive; freeing space permits normal reopen and further writes. Both export and conversation cases passed together. Interactive TUI visibility and final native-platform/candidate qualification remain pending.
