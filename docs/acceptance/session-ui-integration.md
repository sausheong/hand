ResumeSession uses the guard, rejects active background compaction, flushes the current session and retains its runtime/lease until the target is validated and selected. Same-session resume selects metadata without attempting to reacquire its own lease. A failed/busy target leaves the current writer usable. Successful switching updates the application identity and releases the old writer, exposing cleanup/recovery warnings.

The TUI lists sessions with /resume, selects one with /resume <ID>, and names the current session with /name <text>. Names preserve internal spaces. Commands are blocked during active runs/compaction/profile changes as applicable. Resume replaces the transcript with sanitised replay of the selected branch and increments its generation so old events cannot modify the new view. New/resumed sessions clear old transient usage, model-report and timing figures; this avoids falsely attributing another session's metrics but does not implement historical usage restoration.
