## Implemented in the isolated checkout

The workspace Manager binds the real Harness APIs to Catalogue. It migrates and registers legacy workspace keys, reconciles unregistered durable session files within the canonical workspace prefix, opens sessions with writer leases, verifies backend identity against the catalogue and reports backup paths. Busy orphan files remain owned by their live creator; unrelated workspace files are not imported. Missing/replaced backend files and corrupt interior records are explicit errors. Eligible incomplete tails are recovered and backed up before format migration. New sessions use distinct random storage keys and stable header IDs.

CLI startup now resumes the catalogue's last active session; --new-session creates a distinct session while retaining/importing existing history, and --session selects a stable saved ID. The two explicit flags are mutually exclusive. Controller.NewSession switches to a fresh catalogue-backed session, updates the application identity and releases the prior writer. Its compatibility path for internal embedders also uses a fresh backend key instead of Delete. The TUI /new description and result state that previous history is retained; writer cleanup warnings are exposed. Primary Hand's current /new path remains unchanged until this staged patch is integrated.

## Evidence

The compiled-binary regression builds Hand and launches it in three separate processes against a local HTTP fixture: original conversation, independent new session and explicit resume of the original. This is real binary/filesystem integration evidence using a deterministic provider fixture, not live model-quality evidence.

Additional tests cover legacy backup equality, idempotent import, last-active restart, orphan reconciliation, foreign-workspace exclusion, competing writer rejection, an independent new session while another remains active, backend identity replacement, missing files, tail recovery, interior-corruption rejection and controller identity changes. ## Remaining work and limitations

Release approval and native Harness qualification remain pending. The staged checkout has not run Hand's final acceptance checker and cannot satisfy the released-module gate. It still needs /resume and /name interactive flows, fork/tree/export, session usage and attachment metadata, more transactional/fault coverage, UI state reset/replay checks and full native journeys. Session shutdown must join/cancel background compaction before closing the final writer lease; that lifecycle integration is not complete. Creation interrupted before registration is reconciled by prefix discovery, but all concurrent create/register/select interruption cases are not yet qualified. Combined historical duplicate-ID corruption plus a truncated final record still needs a combined migration/recovery path; it currently fails rather than discarding data.

The manager currently returns the record used for selection, whose last-active timestamp can predate the catalogue update; UI metadata consumers should read a fresh catalogue snapshot until that return contract is tightened. Backend/catalogue errors after a committed metadata change require reconciliation rather than assuming rollback. No requirement group is closed by this development result.
