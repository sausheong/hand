# Harness incomplete-tail recovery follow-on

Local candidate: `46dfa7b3f20b3e16189610c7a7ef44276c102689`, based on `ce578590c0e38b3e204bc10b17fb995759449441`. Unpublished and not integrated into Hand, which still uses released Harness v0.3.9. This follows the existing persistence, rewrite, lease and strict-record patches; the earlier release permission request does not cover this new commit.

`Store.LoadRecovering(ctx, agentID, key)` acquires the lifetime writer lease before validation. Only an incomplete final JSON object is repairable. It writes and syncs a private complete-original backup and its directory before atomically replacing the session with the exact validated byte prefix, then syncs the directory again. Unknown fields and whitespace survive. `RecoveryReport` returns the backup location, discarded byte count and whether replacement occurred, including when a later sync fails. Errors release the lease; a returned session owns it until Close. Ordinary Load remains non-mutating. Recovery rejects non-regular files and respects cancellation during reads/copies and before replacement.

Permanent regressions cover original backup equality, exact-prefix preservation, 0600 files, no second repair of valid data, successful append/reload, interior corruption rejection, active-writer exclusion, symlink rejection, first-record interruption, missing sessions, directory-sync fault injection and cancellation after durable backup. Real subprocess tests kill a recovering process at the durable-backup and durable-replacement boundaries and verify restart, backup contents, lease release and subsequent appends.

Validation: 821 full Harness race/coverage tests/subtests passed, zero failures/skips; 1480 session tests/subtests passed across 20 race-enabled repetitions. Session/runtime vet and diff whitespace checks passed. Raw artifacts and hashes are in harness-recovery.json. Tests exercised the unchanged source tree committed above; these are local development results, not final release acceptance.

The API is not integrated into Hand; native Linux execution, broader disk-full/kill-point coverage, complete schema/DAG/version validation, catalogue/migration, selected-leaf persistence and attachments/export remain required.
