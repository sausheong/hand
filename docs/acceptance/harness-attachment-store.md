# Attachment storage foundation

Unpublished Harness `0d55a8f90fdc7dafb5c377f18a9668860aa6111a` adds an attachment package with SHA-256 references, exact byte lengths, 32 MiB per-blob limits and caller-selected store quotas (default 1 GiB). Private synced temporary files are published through exclusive links and a directory-sync fence. Reads validate file identity, length and digest. Linux/macOS writer locks serialise quota admission across store handles. Published content is never evicted; full stores reject new content. Pending-file cleanup and scans are bounded.

Tests cover 12 MiB round-trip/reopen, deduplication, 0600 mode, tampering, traversal/symlinks, concurrent independent-store quota admission, cancellation while waiting for a lock, pending cleanup and limits. Twenty race-enabled repetitions passed (100 test passes). Full race/coverage validation passed 888 tests/subtests, zero failures/skips; vet passed. All four Linux/macOS architecture targets compiled, which is not native execution evidence. The first fixture run used a non-private temporary directory; its failure is preserved, and the fixture was corrected without weakening the private-directory check.

[Patch](harness-attachment-store.patch) and [hashed evidence](harness-attachment-store.json). This is a reusable storage foundation only. Session reference schema, model replay hydration, legacy inline-image migration, copying attachments on fork and portable export are still required. Hand source is unchanged and does not yet call the new package. Primary Hand remains on released Harness v0.3.9. No release or full acceptance is claimed.
